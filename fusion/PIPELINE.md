# UAV-VAD 双分支晚融合 —— 完整前向与评分计算(配真实帧举例)

本文档讲清楚**一帧测试图像如何一路变成最终异常分数**。全程用两帧**真实数据**贯穿讲解,不只给公式:

- **A 帧 = vehicle 测试集第 2086 帧(异常)** —— 外观完全看不出、靠行为补位的例子;
- **B 帧 = bike 测试集第 996 帧(正常)** —— 检测噪声让行为误报、靠检测质量压制的例子。

> 方法论结论与被否决的替代方案见 [README.md](README.md)。本文档只讲前向 + 评分。

---

## 0. 总览

```
                    一帧测试图像  x_t
                          │
        ┌─────────────────┴──────────────────┐
        ▼                                     ▼
 ┌──────────────┐                     ┌────────────────┐
 │  外观分支     │                     │   行为分支      │
 │ RD 反向蒸馏   │                     │ 检测+描述子+kNN │
 └──────┬───────┘                     └───────┬────────┘
        │ 原始分 sa_t                          │ 原始分 sb_t
        ▼                                     ▼
   test 平均秩                            test 平均秩
   p_app_t ∈[0,1]                        p_beh_t ∈[0,1]
        │                                     │
        └──────────────┬──────────────────────┘
                       ▼
       门控 × 检测质量置信  (融合层,无标签、无场景先验)
                       ▼
              每场景 concat 所有 test 帧 → micro-AUC
```

评分口径:**每场景把该场景所有 test 子视频的逐帧分数拼接(concat),算一个 micro-AUC**,与 MADViT 论文口径一致、可直接对比;7 个场景的 AUC 取算术平均为总指标。

### 0.1 训练与产物边界(两分支可并行、互不影响)

| | 外观分支 | 行为分支 |
|---|---|---|
| 是否梯度训练 | **是**(只训 student+OCBE) | **否**(无任何可学习权重) |
| frozen 的部分 | DINOv3 teacher(第三方预训练) | YOLOv8x-VisDrone 检测器(第三方预训练,inference-only) |
| 训练产物 | 每场景一个 `experiments/<exp>/ckpt/<scene>.pth`(student+OCBE 权重+配置) | **"正常点云状态"** = train 正常帧的描述子矩阵 Xtr + logz 的 μ/σ + kNN 索引 |
| conda 环境 / 输入分辨率 | base / 256×256 | DMAD / 640 |

两分支**零共享权重、零数据依赖**,所以外观在 GPU 上训 student 的同时,行为分支跑检测+建点云,可完全并行、互不影响。

> 实现现状:行为分支的"点云状态"目前**未单独序列化成产物文件**,每次出分从 train 帧现场重建(只有检测中心点云缓存在 `behavior/cache/`)。若要像 `.pth` 那样落一个干净产物,可把 `Xtr+μ+σ` 存成 `behavior_<scene>.npz`(待落地)。
> 所以一句话:**梯度训练产物只有外观的 .pth;行为分支的"模型"是正常点云状态。**

## 1. 外观分支:RD 反向蒸馏,top-k 读出

**输入**:整帧 RGB → resize 256×256 → 按 DINOv3 mean/std 归一化。

**三段网络**(student 在正常帧上训 15 epoch,推理时三段全 frozen):
DINOv3 ViT-B/16 teacher 取第 **[5,7,9,11]** 层 patch 特征 → OCBE 瓶颈压成 code(`code_dim=64`)→ 轻量 transformer student 从 code **重建**各层 teacher 特征。学生只在正常帧上学过重建,**遇到异常区域就重建不好**。

**逐帧出分**(`eval.py:score_video` + `model/loss.py:anomaly_readouts`):

1. 每个 tap 层,teacher 特征 `A` 与学生重建 `Â` 都是 `(P, C)`,P≈256 个 patch(16×16 网格)。
2. **每个 patch 算余弦距离** `d_p = 1 − cos(A_p, Â_p)` → 该层 256 个数。重建得好的 patch ≈0,重建差的 patch 偏大。
3. **top-k 聚合(k=5)**:在 256 个 patch 距离里只取**最大的 5 个求均值**。
4. 4 个 tap 求平均 → 帧分 `sa_t`(越大越异常)。

**为什么是 top-k 而不是整帧平均(举例)**:设一帧里异常只占一小块——比如几辆违停车占 10 个 patch、距离 0.5,其余 246 个 patch 是正常路面/草地、距离 ≈0.02。
- 整帧平均:`(10×0.5 + 246×0.02)/256 ≈ 0.039`,异常被绝大多数正常 patch **稀释到几乎看不出**;
- top-5 均值:`≈0.5`,**异常凸显**。
这就是本方法相对 MADViT flatten-cosine 的关键改进(README §top-k)。

**两帧的真实外观分**:
- A 帧(vehicle 异常)`sa = 0.1875`;B 帧(bike 正常)`sa = 0.0670`。
- 注意 A 帧异常,但 vehicle 的异常是"车的行为/拥堵",**车在外观上还是车**,外观分支看不出 —— 下文会看到它的排名正好落在中位(完全没判别力),这正是需要行为分支的原因。

## 2. 行为分支:检测 → 5 维描述子 → logz → 合并 kNN-OOD

**输入**:整帧 RGB(检测器内部 resize 640)。

### 2.1 检测 → 车辆点云
冻结的 **YOLOv8x-VisDrone**(航拍域预训练),只留车辆类,`conf=0.25, iou=0.5, agnostic_nms=True`(跨类 NMS,消一车被 car+van 双标的重复框)。每个框取中心、按图宽高归一化 → 该帧点云 `C={(cx_i,cy_i)}`。无车场景检不出 → 描述子退化为常量 → 自然静默(这是行为分支最重要的假阳屏蔽)。

### 2.2 单帧 5 维描述子(`behavior/l1.py:descriptor`)

| 维 | 定义 | 抓什么 |
|---|---|---|
| `d_min` | 最近一对车的距离 | 近距离/近碰撞 |
| `d_mean` | 平均成对距离 | 整体疏密 |
| `n_close` | 距离 < D0=0.12 的车对数 | 拥堵 |
| `count` | 车数 n | 总流量 |
| `max_local`| 各车 R0=0.10 邻域内邻居数的最大值 | 局部扎堆度 |

n<2 时退化为 `[1,1,0,n,0]`(无对可算 → 设为"很正常")。

**举例:B 帧(bike 正常)的真实描述子**——这帧检测出 6 个框,但其中两个框几乎重叠:
```
d_min=0.0045   d_mean=0.0593   n_close=15   count=6   max_local=5
```
`d_min=0.0045` 说明有两个框中心几乎贴在一起(远小于 D0=0.12),连带 `n_close=15`(15 对车距离都 <0.12)、`max_local=5`(某辆车 0.10 邻域内挤了 5 个邻居)。**这组数字"看起来非常扎堆/拥堵"**——但 bike 是单车环岛、车本来就少,这其实是检测器把零散目标拆成重叠框的**噪声**。记住这帧,§3 会看到它如何骗过行为分支、又被检测质量挡下。

**对照:A 帧(vehicle 异常)的真实描述子**:
```
d_min=0.1265   d_mean=0.3421   n_close=0   count=6   max_local=0
```
车不算多,但 `d_mean=0.34` 偏小、`count` 相对该子视频的正常段偏高,是轻微聚拢趋势。

### 2.3 正常点云(合并训练)
该场景**所有 train 子视频**的逐帧描述子合并成矩阵 `Xtr (N×5)`。合并比分 seq 更密、参照更多;kNN 的局部性让不同 seq 自然落在各自邻域,单一尺度使 concat 天然可比(README)。

### 2.4 预处理:logz(联合 kNN 之前消除"尺度裹挟")
直接 z-score 的问题:计数维(n_close/count/max_local)**重尾**——某帧车暴增就把 std 撑大、并在欧氏距离里单点主导,把 `d_min` 这类真信号淹没(highway 反相关的成因)。故**先压尾再标准化**:对计数维取 `log1p`(=log(1+x)),再对全 5 维做 z-score(μ/σ 取自 logz 后的 train)。

**举例:B 帧经 logz 后**(原始 → log1p → 减 train 均值除 std):
```
            d_min   d_mean  n_close  count  max_local
原始        0.0045  0.0593   15       6      5
logz 后    −0.694  −2.035  +2.384  +0.333  +2.452     ← z 分数(偏离正常多少个 σ)
```
`n_close=+2.38σ`、`max_local=+2.45σ` —— 在"扎堆"两个维上离正常 2 个多标准差,行为分支会判它很异常(下一步证实)。

logz 是**零负作用的全局改进**(highway/vehicle/crossroads 行为分同时小涨,其余不变);robust / rankU / rankN / maha 均被它压过(README 预处理消融)。

### 2.5 合并 kNN-OOD 出分
test 帧做同样 logz 变换得 `z_t`,在正常点云里找 **K=8** 个最近邻,取**平均距离** `sb_t`(越远 = 越偏离正常车流 = 越异常)。

**两帧真实行为分**:
- B 帧(bike 正常):`sb = 0.9305` —— 因为那两个重叠框制造的"扎堆"离正常很远,行为分支**误判为异常**(这是检测噪声导致的假阳);
- A 帧(vehicle 异常):`sb = 0.3508` —— 行为捕捉到"车偏多+间距偏小"的聚拢,判其偏异常。

## 3. 融合层:门控 × 检测质量置信(核心,无路由)

`sa_t`(余弦距离)和 `sb_t`(欧氏距离)量纲完全不同,直接相加会被大尺度那支裹挟。分三步:**标准化 → 检测质量 → 门控加权**。

### 3.1 标准化:test 自身平均秩
对每场景,把该分支**所有 test 帧分数**转成**平均秩百分位** ∈[0,1]:一个分数排在所有 test 帧的第几名(0=最低,1=最高;平局取中间名次)。

- **保序无损**:单调变换,单分支 AUC 完全不变,只是把两支放到同一 [0,1] 刻度;
- **必须用平均秩**:否则大量相同分(无车帧 kNN=0,占比可达 99%)会被 argsort 排成伪随机名次、凭空注入噪声;
- **必须用 test 自身分布、不用 train-CDF**:外观分有强 train→test 漂移,test 分整体超出 train 范围,用 train-CDF 会饱和到 1、把正常异常糊一起(bike 98→58)。见记忆 `uav-vad-fusion-score-normalization`。

**两帧标准化后**:
| 帧 | 外观 sa → p_app | 行为 sb → p_beh |
|---|---|---|
| A(vehicle 异常) | 0.1875 → **0.501** | 0.3508 → **0.837** |
| B(bike 正常) | 0.0670 → **0.300** | 0.9305 → **0.999** |

读这两行:A 帧外观 `p_app=0.501` —— 排在正中间,等于**外观对这帧毫无意见(抛硬币)**;行为 `p_beh=0.837` 明确偏异常。B 帧外观 `p_app=0.300` 正确判偏正常;但行为 `p_beh=0.999` 几乎顶格报异常(检测噪声假阳)。

### 3.2 检测质量置信 q(场景级,只用 train)
行为依赖前置检测,检测烂(目标闪烁)→ 描述子全是噪声 → 行为不可信。用 **train 帧的帧间车数波动**度量(不碰 test):车数序列每帧之间跳得越厉害,说明检测越不稳。

```
jitter = mean(|相邻帧车数之差|) / mean(车数)     # 在每个 train seq 内算
q      = min(1, 0.1 / jitter)                    # 车数帧间变化<10% 算"稳",越抖 q 越小
```

7 场景实测:

| 场景 | jitter | q | 解读 |
|---|---|---|---|
| highway | 0.061 | **1.000** | 检测稳 → 行为不降权 |
| vehicle | 0.079 | **1.000** | 满车流稳 → 行为不降权 |
| crossroads | 0.106 | 0.946 | 尚可 |
| **bike** | 0.290 | **0.345** | 车少框小、检测抖 → 行为压到 1/3 |
| solar | 0.928 | 0.108 | 几乎无车 → 行为压掉 |
| farmland | 1.481 | 0.068 | 几乎无车 → 行为压掉 |
| railway | 2.005 | 0.050 | 几乎无车 → 行为压掉 |

> q 度量"**行为这路证据可不可信**",**不是**"哪个场景是行为异常"的类型先验,所以本方法仍属**无路由**——没有任何人工把某场景指派给某分支。

### 3.3 门控加权(逐帧)
两个置信相乘,行为只有在 **(检测可信 q 高) 且 (外观不笃定) 且** 时才获得发言权:
```
base_w = 1 − 2|p_app − 0.5|        # 外观越笃定(p_app 接近 0 或 1)→ base_w 越小 → 行为越靠边
w      = 0.5 · q · base_w          # 再乘场景检测质量;0.5 = 行为权重上限
fused  = (1 − w)·p_app + w·p_beh
```

### 3.4 两帧走完整流程(这是关键,逐步看数字怎么变)

**A 帧 —— vehicle 异常,外观瞎、行为补位(q=1)**
```
p_app = 0.501  （外观抛硬币,完全没判别）
p_beh = 0.837  （行为说"偏异常"）
q     = 1.000  （vehicle 检测稳,行为可信)
base_w = 1 − 2|0.501 − 0.5| = 0.998     # 外观极不笃定 → 几乎放满行为
w      = 0.5 × 1.000 × 0.998 = 0.499    # 行为拿到接近上限 0.5 的权重
fused  = (1 − 0.499)×0.501 + 0.499×0.837
       = 0.501×0.501 + 0.499×0.837
       = 0.251 + 0.418 = 0.669
```
→ 这帧从外观的 **0.501(瞎猜)被行为拉到 0.669(明确偏异常)**。外观对 vehicle 的行为异常毫无办法,正是检测质量稳的行为分支把它救了回来。这解释了 vehicle 融合后 60.71→**69.27(+8.56)**。

**B 帧 —— bike 正常,检测噪声让行为误报、被 q 压制(q=0.345)**
```
p_app = 0.300  （外观正确:偏正常）
p_beh = 0.999  （行为假阳:被两个重叠框骗成"顶格异常"）
q     = 0.345  （bike 检测烂,行为不可信)
base_w = 1 − 2|0.300 − 0.5| = 0.600
w      = 0.5 × 0.345 × 0.600 = 0.103    # q 把行为权重从可能的 0.30 压到只剩 0.103
fused  = (1 − 0.103)×0.300 + 0.103×0.999
       = 0.897×0.300 + 0.103×0.999
       = 0.269 + 0.103 = 0.372
```
→ 行为想把这帧顶到 0.999,但 q=0.345 把它的权重压到 10%,**最终 fused=0.372 仍然偏正常**,没有误报。
**反事实**:若像之前那样**不乘 q**(只有外观门控),则 `w=0.5×0.600=0.30`,`fused=0.7×0.300+0.30×0.999=0.510` —— 这帧会被错误顶到 0.51(偏异常),正是这种帧让 bike 融合后从 98.08 掉到 94。乘上 q 之后,bike 回升到 **97.40**。

## 4. 最终结果(7 场景 concat micro-AUC,%)

| 场景 | 纯外观 | 门控×q 融合 | Δ |
|---|---|---|---|
| highway | 92.69 | **94.08** | +1.39 |
| farmland | 99.47 | 99.47 | −0.00 |
| bike | 98.08 | 97.40 | −0.68 |
| solar | 86.11 | 86.09 | −0.03 |
| vehicle | 60.71 | **69.27** | +8.56 |
| crossroads | 59.68 | 59.31 | −0.37 |
| railway | 95.92 | 95.92 | +0.00 |
| **均值** | **84.67** | **85.93** | **+1.27** |

逐级贡献:base 门控 84.91 → +logz 预处理 85.35 → +检测质量 q **85.93**。
**全程无路由、无异常类型先验**:检测烂的场景靠 q 自动降权回纯外观(B 帧),外观漏检的 vehicle/highway 靠行为补位提分(A 帧)。
(需要一条"行为只在拥堵场景参与"硬先验的路由方案可达 88.06,见 README §路由;本方案用 +1.27 换零先验。)

## 5. 复现

```bash
# 外观逐帧分数(base 环境)→ experiments/da/fusion/legacy_score_dump/scores/app_<scene>.npz
HF_HUB_OFFLINE=1 python fusion/dump_appearance_scores.py

# 行为 + 融合(DMAD 环境)
conda run -n DMAD python fusion/scale_probe.py     # 预处理消融(base/robust/logz/rankU/rankN/maha)
conda run -n DMAD python fusion/gate_logz.py       # logz 接门控
conda run -n DMAD python fusion/gate_q.py          # 门控 × 检测质量 q(最终方案,§4 表)
conda run -n DMAD python fusion/example_trace.py    # 抽真实帧打印全链路数值(本文档 A/B 帧的来源)
```

- 行为 per-dim/聚合诊断:`fusion/desc_probe.py`;标准化验证:`fusion/verify_percentile.py`。
- 分数产物落 `experiments/da/fusion/legacy_score_dump/scores/`(已 gitignore)。各步实验依据与被否决方案见 [README.md](README.md)。
