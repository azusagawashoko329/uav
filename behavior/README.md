# 行为分支(behavior branch)

> **状态：已舍弃（2026-11-04）。** 行为分支不再开发、不再更新 AUC 统计，也不进入主对比或融合；当前模型只保留外观蒸馏分支（DINOv3-RD）。以下内容是历史归档，数字不再维护。

外观分支(`model/` + `train.py` + `eval.py`,DINOv3 反向蒸馏)在 **vehicle / crossroads** 这类
"异常藏在车之间的关系/位置里"的场景上接近瞎猜。行为分支补这个位。

**刻意叫"行为"而非"运动"**:经数据核查(`dataset/README_codex.md` 逐子视频审计),本数据集异常是
①车间距离/拥堵 ②车占错区域/压线 ③外观类(新物体/路面态),**没有真正需要轨迹/逆行时序建模的异常**。
所以行为分支**坍缩成单帧、无跟踪、无时序**,输入与外观分支一致(单帧),融合更省事。
独立于外观:不共享参数/梯度,只共享数据集与评测协议。运行在 **DMAD conda 环境**(有 ultralytics)。

## 异常类型 → 归属

| 异常 | 出现 | 归属 |
|---|---|---|
| 拥堵 / 密集停车 | crossroads-s1、vehicle-s2 | **行为 L1(距离+车数+打包)** |
| 占错区(s2 红色候车区)/ 压白线(s3-01)/ 违规横穿(s3-02、s3-03) | crossroads-s2/s3 | **单帧行为分支不可达 → limitation(见末)** |
| 行人闯入(被误检成 motor) | vehicle-s1 | 上游检测失能 → 外观 |
| 新类别、行人/动物、路面覆沙 | bike、highway 全部 | **外观分支** |

**highway 整支放弃**:训练就含静止车 → d_min 本来就低 → 测试近碰撞也是"合法 min";且近碰撞那刻
小车被货车遮挡(两车并成一个检测框,距离失明)。外观在 highway 已近 SOTA(92.7),留给它。

## L1 前向(单帧)+ 训练/测试口径(重点)

把"检测前端"和"训练/测试"分开看:

1. **检测(前端,逐帧,缓存)**:每个子视频的**每一帧(train 和 test 都要)**→ yolov8x(agnostic_nms,
   conf 0.25,仅车辆类)→ 车框 → 中心归一化到 [0,1]。**两个 split 都检测,只是因为 train 帧要拿去堆点云、
   test 帧要拿去打分——检测本身不是训练,与"按子视频训练"无关。** 缓存,换描述子/打分器不用重检测。

2. **描述子(逐帧,5 维)**:
   - `d_min` 最近一对车距离(近碰撞→极小)
   - `d_mean` 全体两两均距
   - `n_close` 距离 < `D0=0.12` 的对数
   - `count` 车辆数 —— 抓 vehicle-s2(车更多但间距≈正常:面积随车数同涨→"车/面积"不变→失能,只有总数变)
   - `max_local` 各车 `R0=0.10` 内邻居数的**最大值** —— 抓 crossroads-s1(镜头移动下"20 散开 vs 20 挤成团"
     车数都=20,count 失能;打包度只看局部聚集,与总数/镜头区域无关)
   - 不足 2 辆车 → `[1,1,0,n,0]`(无交互=正常)

3. **训练(建正常点云,无梯度)= 和外观分支一致的口径**:把该场景**所有 train 子视频(跨全部 seq)的每一帧**
   描述子收集到一起 → **一个合并的正常点云**(crossroads ≈ 15772 点)。不分 seq、不分子视频,全场景 train 合一锅。

4. **测试(按 seq 单独打分)**:每个 test 子视频的帧,逐帧 z-score(用 train 点云的均值/标准差)→ 在合并点云里
   找 **K=8** 个最近正常点 → **异常分 = 平均距离**。注意:测试帧比的是**那一个合并点云**(不是某 seq 自己的点云)。

5. **评测**:逐子视频(seq)各算 `roc_auc_score(标签, 分数)×100`;另给全场景 concat。

```
帧(train+test)─▶ yolov8x检测+agnostic_nms ─▶ 中心 ─▶ 5维描述子
   train全合并 ─▶ 正常点云(一个)        ┐
   test每帧 ─────────────────────────────┴▶ 合并kNN-OOD(到8近邻均距) ─▶ 逐seq AUC
```

**打分器选型(实测,均在合并训练下)**:合并 kNN > 分-seq kNN > LOF。合并点云**正常参照更多更密**→ 正常帧
有近邻、异常帧离所有正常都远 → 分离最好(crossroads-s1 dist 单项:分-seq 60.5、LOF 47.3、**合并 kNN 77.9**)。
单一尺度使 concat 天然可比,无需 d_norm。**ego-motion 对单帧成对距离天然共模抵消,不是问题。**

## L1 结果(2026-06-13,yolov8x+agnostic-NMS,合并 kNN-OOD,逐 seq)

**看逐 seq,不要看 concat**——concat 把 L1 该管的拥堵 seq 和不该管的压线 seq(L2 的活)混在一起,看不出真本事。

**crossroads**(外观 RD-topk 59.7):
| 特征 | s1 堵塞 | s2 压线 | s3-01 | s3-02 | s3-03 |
|---|---|---|---|---|---|
| dist(3) | 77.9 | 41.2 | 58.4 | 44.3 | 51.9 |
| +count | 84.6 | 32.2 | 64.6 | 47.0 | 52.0 |
| **+both** | **88.4** | 35.2 | 66.4 | 50.7 | 51.7 |

**vehicle**(外观 RD-topk 60.7):
| 特征 | s1(行人,巧合) | s2 拥堵 |
|---|---|---|
| dist(3) | 82.9 | 63.0 |
| **+count** | 82.8 | **85.1** |
| +both | 83.0 | 82.3 |

**结论:**
- **crossroads-s1 堵塞:64 → 88.4**(合并训练 + 车数 + 局部打包叠加)。`max_local` 打包确实在 count 之上再 +3.8,
  印证"镜头移动下要看局部聚集不是总数"。
- **vehicle-s2 拥堵:63 → 85.1**(车数为王);packing 对 vehicle 略稀释。
- 特征小权衡:crossroads 吃 +both(88.4),vehicle 吃 +count(85.1)。两个目标都已 82~88;取固定 [all5] 即可。
- **L1 在职责范围(拥堵)内很好**(s1=88.4、vehicle-s2=85.1);压线 seq(crossroads-s2/s3 反向/≈50)是 **L2** 的活,
  不该由 L1 出分 → 融合时需 do-no-harm(L1 在压线 seq 上别乱报)。

### L2(目标-场景)调研后否决 —— 记为 limitation

设想过用"目标局部表面外观 + 类别"的 kNN-OOD 抓 占区/压线(红车道纹理 vs 灰沥青)。**否决,因为单帧被污染**:
红色候车区、白色车道线这类"禁区/标线",**正常车辆也会经过/压到**(候车区本就是通行用的,变道会压线)→
训练正常帧里就有"car 在红区 / car 贴白线" → 不 OOD。真正区分违规与正常的是**停驻/逗留**(在错的地方停下不走),
这是**时序**信息;单帧表面描述子拿不到,再为它引入帧窗则整条分支过重、得不偿失。机位逐子视频变化也已枪毙坐标先验。
- crossroads-s2(占红色候车区)、s3-01(压白线):污染,单帧不可达。
- crossroads-s3-02/03(自行车违规横穿):motor 本就合法在沥青上 + 类别被 bike→motor 搞混 + 异常是轨迹 → 不可达。
- vehicle-s1(行人误检成 motor):上游检测失能,不归本分支(L1 在此偶然偏高是"错有错着")。

**诚实承认:行为分支不优化所有场景。** 干净的贡献就是 L1 的 crossroads-s1 + vehicle-s2,其余记为已知 limitation。
